已完成RocketMQ 定位与架构鸟瞰

概念

本章先记住 3 件事
  • 干什么：让业务系统异步解耦，不必同步等所有下游完成。
  • 谁协作：Producer、Broker、Consumer、NameServer 四个角色分工明确。
  • 怎么走：先向 NameServer 查路由，再直连 Broker 收发消息。

① 解决什么问题？

Apache RocketMQ 是分布式消息中间件：上游把事件「投递出去」即可返回，下游按自己的节奏消费。

  • 异步解耦 — 下单后发消息，库存/短信/积分各自消费，互不强依赖。
  • 削峰填谷 — 秒杀流量先写入队列，后台慢慢处理，保护数据库。
  • 最终一致 — 配合事务消息等能力，在分布式场景下保证业务一致。

② 四大角色（对照下图）

Producer 生产者

业务系统内负责发消息的客户端，只配置 NameServer 地址。

Broker 代理

存消息、投递消息的核心服务；CommitLog 持久化，支持主从复制。

Consumer 消费者

在消费组内收消息，同组负载均衡，不同组互不影响。

NameServer

NameServer 维护 Topic→Broker 路由表，无状态、可集群，类似轻量注册中心。

③ 一条消息怎么走？（4 步）

sequenceDiagram
  autonumber
  participant P as Producer
  participant NS as NameServer
  participant B as Broker
  participant C as Consumer
  P->>NS: 查询 Topic 路由
  NS-->>P: 返回 Broker 与 Queue
  P->>B: 发送消息
  C->>NS: 查询 Topic 路由
  C->>B: 拉取 / 接收消息
  1. Producer 问路由 — 带着 Topic 名问 NameServer：这个 Topic 在哪些 Broker、哪些 Queue？
  2. Producer 发消息 — 按路由选一个 MessageQueue，把消息写到 Broker。
  3. Consumer 问路由 — 同组 Consumer 也向 NameServer 拿同一份路由。
  4. Consumer 收消息 — 从 Broker 拉取或 Push 投递，业务处理完后提交消费位点。

④ 和 Kafka / RabbitMQ 怎么选？

对比项RocketMQKafkaRabbitMQ
典型场景电商/金融、事务与定时消息日志采集、流式计算复杂路由、AMQP 生态
分区单元MessageQueuePartitionQueue（经 Exchange 路由）
元数据/路由NameServer（轻量）ZooKeeper / KRaftBroker 内置
特色能力顺序、延迟、事务消息原生支持超高吞吐、生态成熟灵活路由、低延迟小消息
何时优先选Java/Spring 栈 + 事务/定时/顺序大数据管道、流处理协议标准、路由规则复杂

// 代码印证「只配 NameServer」：Broker 地址由路由动态获得
DefaultMQProducer producer = new DefaultMQProducer("order_producer_group");
producer.setNamesrvAddr("127.0.0.1:9876");
producer.start();

Message msg = new Message("TopicOrder", "TagCreate",
    "order-1001".getBytes(StandardCharsets.UTF_8));
producer.send(msg);  // 内部：查路由 → 选 Queue → 发往 Broker

DefaultMQPushConsumer consumer = new DefaultMQPushConsumer("order_consumer_group");
consumer.setNamesrvAddr("127.0.0.1:9876");
consumer.subscribe("TopicOrder", "TagCreate || TagPay");
consumer.registerMessageListener((msgs, ctx) ->
    ConsumeConcurrentlyStatus.CONSUME_SUCCESS);
consumer.start();

测验：RocketMQ 定位与架构鸟瞰

1. （单选）下列哪一项不是本章强调的 RocketMQ 典型价值？

消息队列是补充同步调用，不是取代一切 RPC。

答案：C — MQ 解决异步与削峰，不是把所有调用都改成消息。

2. （填空）Producer 与 Consumer 在收发消息前，通常先向 ______ 查询 Topic 的路由信息（Broker 与 Queue 列表）。

轻量、无状态的路由注册中心，不是 ZooKeeper。

答案：NameServer（也接受 nameserver，大小写不敏感）

3. （多选）下列属于 RocketMQ 架构中「四大角色」的是？

Kafka 依赖 ZooKeeper/KRaft；RocketMQ 用 NameServer 做路由。

答案：A, B, D, E — Producer、NameServer、Broker、Consumer；不含 ZooKeeper。

4. （单选）关于消息流转，下列描述正确的是？

对照本章时序图四步：查路由 → 发/收 → Broker 存储。

答案：B — D 错在同组是负载均衡（一条只被一个实例消费），C 错在存储在 Broker。
